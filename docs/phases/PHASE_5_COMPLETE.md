## What shipped

### Findings (`45310f3`, `0664c20`, `d015a2f`)

- **Engine (`spektr-engine::findings`):** create, edit, status (`draft → ready → sent`), delete, link entities and evidence, and candidates.
  - **Checks** come from the rules profile's `[lints]`: claim and relevance written; a URL or screenshot; no blocked news or aggregator domains; not used in another category; the tracelabs approval warning; an unknown category.
  - `ready` needs every `✕` check to pass, and `sent` needs `ready`.
  - Creating a finding from an entity attaches that entity's captures as evidence.
  - The title starts as the claim's first 60 characters (or `<category> · <entity>`) and follows the claim until it's edited by hand.
- **Export (`spektr-engine::export`), shared by the CLI and the TUI:**
  - `tracelabs`: paste-ready submission text (`Category: X (1,000 pts)`, Claim, Relevance, URL, Screenshot)
  - `md`: a `## Case` summary (seeds, graph by type, review pending), then the findings
  - `json`: the whole case, with `--with-blobs`
  - `spektr export --format tracelabs|md|json [--finding N]…`
- **The Findings screen (`F`, artboard 09):**
  - categories with findings first, points, `[all] draft ready sent` tabs, totals and open value
  - the detail: claim, relevance, supporting entities with strength, checks, and evidence with the capture image
  - `n` new, `e` the inline editor (ratatui-textarea), `E` `$VISUAL`/`$EDITOR`
  - `a` attach evidence, `r` ready, `s` sent, `d` delete, `↵` go to entity
  - `x` export: submission text to the clipboard, or Markdown/JSON to a file
  - `f` files a finding from any entity, and from a checklist item (J7 step 5); `:export` and `:finding new` in the palette

### The tutor (`a417184`)

- `spektr tutor [--reset]`, `:tutor`, `:tutor reset`. Ten lessons (TUI_SPEC §10):
  1. move and focus
  2. seed a username
  3. run a playbook
  4. pivot and go back
  5. read strength
  6. review and confirm an avatar match
  7. the timeline
  8. capture and the checklist
  9. write a finding
  10. pass the checks and export
- **Offline:** every fixture is bundled into the binary (`spektr-modules::bundled`, kept in step with `fixtures/` by a test). In the tutor, every module and capture replays from them, and launchers and viewers are recorded, not opened.
- **The case:** a tracelabs case in the state dir (subject Jordan Marlow, last seen 2026-09-28).
- **Advancing:** each step completes on a semantic event (a seed, a playbook started or finished, a capture, a finding passing its checks, an export), or on a state change: pane, tab, help, focus, inspector, avatar edge, late activity, account count. A key alone never completes a step.
- A two-row coach strip above the status line and a TUTOR pill. Progress is saved to `<state>/tutor.toml` and resumed.
- The launcher points first-time users at the tutor (PRD J1).

### Module tooling (`8b7bb9a`)

- `spektr module new <name> --lang python|rust|shell`:
  - scaffolds `module.toml`, the program, a README and a fixture
  - templates in `crates/spektr/templates/module/`, all on fictional `example.com` URLs
- `spektr module test <dir> --input <type>:<value>` runs it once in a temporary engine and prints what it emitted, with validation errors.
- `spektr module check <dir>` checks:
  - the manifest against the vocabulary
  - fixtures and replay
  - that no secrets appear in fixtures
  - that the module exits within 2 s
- `spektr module install <dir> [--update] [--yes]`:
  - shows the module's hosts, secrets and technique, asks, then copies it
  - pins it to a tree hash (`.spektr-pin`); a module whose files change stays off until `--update` re-approves it
- `spektr module list | info | enable | disable`, with the disabled list in `<config>/modules/.disabled`. Built-ins can be disabled too.

## Deviations from the spec, and why

1. **No new default key bindings.** The Findings bindings (`n e E a r s x d ↵`) were in the registry from Phase 3. Evidence rows open with `↵`. The artboard's `o open screenshot  O open html` would add new default bindings, which is Jay's call (DISPATCH), so they're not bound.
2. **The title follows the claim with no schema change.** A title equal to the automatic one for the old claim is treated as automatic. Writing a different title stops it following.
3. **The Markdown export starts with a case summary** (`## Case`: seeds, graph by type, pending review), so J6's report says something even with no findings.
4. **Module pins and the disabled list are files** (`<module>/.spektr-pin`, `<config>/modules/.disabled`). They aren't case-file data, so the case schema is unchanged.
5. **The Rust module template depends on `spektr-protocol` from crates.io.** It builds only once the crate is published (J4 uses the Python template).
6. **Tutor key scripts use `~` for a pause.** It's a pause for loading, and after `esc`, because an escape followed at once by a key reads as Alt+key. `e2e_tutor` drives the lessons from these scripts, so the hints and the test can't drift apart.
7. **`/` starts a fresh filter.** It used to extend the previous filter text, so a second search in a session matched nothing (found by `e2e_tutor`).
8. **The demos render in CI only.** VHS isn't installed on this Mac, and installing it isn't my call. See Known issues for what I checked.
9. **The release dry run is dist's PR mode, not a separate workflow.** `pr-run-mode = "upload"` builds every target on each PR, which is what the exit criterion asks for. A tag publishes.
10. **crates.io publishing is a separate workflow** (`publish-crates.yml`). dist publishes binaries and the formula; `cargo publish --workspace` publishes the seven crates in dependency order.
11. **Every fixture is bundled into the binary,** not only the tutor's. They're all fictional, and `bundled.rs` stays a 1:1 table that a test checks against `fixtures/`. They add 152 KB of JSON lines to the binary.

## Known issues

- **Publishing is Jay's step.** Nothing has been published. It needs:
  - an `infktd/homebrew-tap` repository
  - the `HOMEBREW_TAP_TOKEN` and `CARGO_REGISTRY_TOKEN` secrets
  - then `git tag v0.1.0 && git push --tags`
- **A terminal that never answers DA1 loses the first keystroke.** `images = "auto"` queries the terminal at startup through `ratatui-image`, which waits 2 s. Its reader thread then stays blocked on stdin and swallows the first key. Every common terminal answers DA1. The workaround is `images = "halfblocks"`.
- **The Kitty and iTerm2 screenshots are still Jay's step** (PHASE_4_QA § Real terminal).
- **There are no screenshots in the fixture case:** replay never starts a browser. Findings evidence shows `text/html` captures. The image block is covered by snapshots and by Phase 4's live image preview.
- **A replay miss reads `no fixture for GET …`** in the rail. That's test-only wording; on the network it's the HTTP error.
- **Toasts don't expire under `SPEKTR_CLOCK`** (unchanged from Phase 4).

## How Jay can test it

1. **The tutor:** `cargo run -p spektr -- tutor`. Work through it from the coach strip alone; it should take about 15 minutes, offline. Quit halfway and run it again: it resumes. `spektr tutor --reset` starts over.
2. **A finding:** in the tutor's case, or your own with `--profile tracelabs`:
   - put the cursor on an account and press `c` to capture, then `f`
   - pick a category with `← →`, write the claim, ↵
   - `e` to add the relevance; watch the checks turn `✓`
   - `r`, then `x` → Submission text, and paste it somewhere
3. **The headless export:** `spektr export <case> --format md > report.md` and read the report.
4. **Write a module:**
   - `spektr module new lemmy --lang python`
   - `spektr module test ./lemmy --input username:example --fixture lemmy/fixtures/username_example.jsonl` (offline; without `--fixture` it really requests `example.com`)
   - `spektr module check ./lemmy`
   - `spektr module install ./lemmy`
   - append a line to `~/.config/spektr/modules/lemmy/main.py` and run `spektr module list`: it shows `changed · needs install --update` until you re-approve it
5. **The release dry run:** on the PR, open the `Release` run and download its artifacts (four tarballs, `spektr-installer.sh`, `spektr.rb`). The `demos (VHS)` job's artifact has the four GIFs.
6. **Publishing, when you're ready:**
   - create `infktd/homebrew-tap`
   - add the `HOMEBREW_TAP_TOKEN` and `CARGO_REGISTRY_TOKEN` secrets
   - tag `v0.1.0`
